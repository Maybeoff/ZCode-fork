ZCode — это рабочее пространство для AI-программирования, предоставляющее десктопное приложение, браузерный интерфейс и терминальный агент. Этот репозиторий содержит клиенты, серверные сервисы, общий UI, а также исходный код Agent CLI и runtime.

## Инициализация

Подготовьте Git, Node.js **24.14.0** и pnpm **10.33.2**; версии указаны в [mise.toml](mise.toml). Все команды разработки и сборки выполняются из корня репозитория.

```bash
pnpm bootstrap
```

`pnpm bootstrap` устанавливает зависимости workspace, подготавливает ресурсы локального запуска десктопа, затем выполняет `build:bootstrap`.

Исходный код Agent CLI и runtime находится в [apps/zcode-cli/](apps/zcode-cli/) и клонируется вместе с репозиторием как обычная директория — отдельно тянуть Git submodules не нужно.

При необходимости выберите другие точки входа инициализации или сборки:

| Команда                           | Назначение                                                              |
| --------------------------------- | ----------------------------------------------------------------------- |
| `pnpm install`                    | Установка зависимостей                                                  |
| `pnpm prepare:desktop-runtime`    | Подготовка ресурсов десктопного запуска, по умолчанию включая удалённые |
| `pnpm prepare:remote-assets`      | Отдельная подготовка ресурсов удалённого запуска                         |
| `pnpm bootstrap:with-remote`      | Инициализация зависимостей, локальных и удалённых ресурсов с последовательной сборкой пакетов; пропускает bundle десктопа |
| `pnpm build`                      | Рекурсивно выполняет скрипты сборки всех пакетов workspace, включая шаги подготовки ресурсов внутри пакетов |

По умолчанию `bootstrap` пропускает подготовку удалённых ресурсов — это подходит для локальной десктопной разработки. При использовании удалённых workspace или проверке ресурсов удалённого релиза запускайте соответствующие команды подготовки.

## Разработка и запуск

### Десктопная версия

```bash
pnpm dev:desktop

# С использованием тестового окружения
pnpm dev:desktop:test
```

`pnpm dev:desktop` по умолчанию эквивалентен `pnpm dev:desktop:prod` и использует конфигурацию production-сервисов. Скрипт запуска подготавливает локальные ресурсы запуска, собирает десктопного агента, затем запускает Electron и слежение за исходниками.

Для разработки с отдельным каталогом данных можно задать `ZCODE_DATA_BASE_DIR`. Например, в macOS / Linux:

```bash
ZCODE_DATA_BASE_DIR="$HOME/.zcode-dev-home" pnpm dev:desktop:test
```

### Удалённые функции (SSH/WSL)

Сначала выполните `pnpm bootstrap:with-remote` для подготовки удалённых ресурсов (mock-cdn), затем `pnpm dev:desktop`; при подключении к удалённому проекту в выборе ресурсов укажите «Скачать локально и загрузить». В режиме разработки ресурсы берутся из локального `packages/desktop/mock-cdn` и локальных артефактов сборки, загружаются на удалённый узел по SFTP, без обращения к CDN.

### Веб-разработка

При изменении исходного кода Web или серверной части используйте режим разработки:

```bash
pnpm dev:web

# Указание серверного workspace (macOS / Linux)
ZCODE_SERVER_WORKSPACE=/path/to/project pnpm dev:web
```

Команда одновременно запускает dev-сервер Web (по умолчанию `http://localhost:5173`) и серверную часть (по умолчанию `http://localhost:3030`); в браузере открывайте первый адрес. Запросы `/ws` и обычные `/api` проксируются на локальный сервер, `/api/v1/oauth/token` — отдельно на текущий настроенный продуктовый сервис.

После изменения исходного кода агента выполните `pnpm --filter @zcode/cli... build` и перезапустите сервис. Для проверки полного релизного пакета распакуйте и запустите его, как описано в главе «Сборка консольной версии ZCode» ниже.

### Консольная версия ZCode

Консольный релизный пакет содержит TUI, Web и агента; всё запускается единой командой `zcode`: без аргументов — вход в TUI; если первый аргумент `--web` — запуск Web; остальные аргументы передаются существующему Agent CLI. Оба режима работают локально, без Electron.

```bash
# По умолчанию вход в терминальный интерфейс
zcode

# Запуск веб-интерфейса
zcode --web

# Указание проекта и порта, без автоматического открытия браузера
zcode --web --workspace /path/to/project --port 3030 --no-open

# Просмотр параметров CLI или Web
zcode --help
zcode --web --help
```

В Web-режиме рабочий каталог по умолчанию — текущий, прослушивание — `127.0.0.1`, токен доступа по умолчанию не выдаётся, свободный порт выбирается автоматически и браузер открывается сам. Откройте адрес из терминала; остановка — `Ctrl+C`. Для доступа из локальной сети используйте `--host 0.0.0.0`; при прослушивании нелокальных адресов по умолчанию генерируется токен доступа — используйте выведенную в терминал ссылку с токеном. Токен можно задать через `--token` или отключить через `--no-token`.

При прямом запуске HTTP-входа общего веб-сервиса аутентификацию API/WebSocket настройте через `ZCODE_SERVER_AUTH_TOKEN`; при создании сервиса через программный интерфейс используйте опцию `authToken`.

Способ сборки описан в главе упаковки ниже. `pnpm build:zcode` только создаёт релизный пакет и не заменяет уже установленный в `PATH` `zcode`. Если команда всё ещё указывает на старую установку или другой каталог исходников, проверьте через `command -v zcode` в macOS / Linux или `where.exe zcode` в Windows.

### Разработка CLI из исходников

При прямой разработке TUI или агента запускайте входную точку исходников:

```bash
pnpm --filter @zcode/cli dev --help
pnpm --filter @zcode/cli dev

# Сборка CLI и его workspace-зависимостей
pnpm --filter @zcode/cli... build
node apps/zcode-cli/packages/cli/dist/zcode.cjs --help
```

Эта точка входа напрямую запускает Agent CLI, минуя разделение через `--web` в релизном пакете. Для веб-разработки используйте `pnpm dev:web`; для проверки единой команды `zcode` используйте `bin/zcode.mjs` из распакованного архива ниже.

### Разработка UI-плагинов

См. [UI Plugin：возможности、API и отладка](UI_PLUGIN.md): пример совместной работы на холсте в Excalidraw расскажет про установку и обновление плагинов, page API и точки совместной отладки с хостом.

**При отправке PR с плагином в `zcode-plugins` обязательно укажите в шаблоне PR, является ли он UI Plugin, и укажите его название.** Критерии см. в разделе [Указание типа плагина при отправке PR](UI_PLUGIN.md#提交-pr-时声明插件类型).

## Конфигурация

Примеры адресов сервисов и настроек сборки — в [.env.example](.env.example) в корне репозитория; при необходимости скопируйте в `.env`, а локальные переопределения положите в `.env.local`. Окружение разработки Desktop выбирается через `dev:desktop:test` / `dev:desktop:prod`.

| Переменная                          | Назначение                                                  |
| ----------------------------------- | ----------------------------------------------------------- |
| `ZCODE_DATA_BASE_DIR`               | Базовый каталог данных приложения; данные пишутся в `.zcode/` внутри него |
| `ZCODE_SERVER_WORKSPACE`            | Путь workspace серверной части Web                          |
| `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` | Путь к локальному файлу конфигурации провайдеров; если не задан — используется встроенная конфигурация |
| `ZCODE_DIST_BASE_URL`               | Корневой адрес загрузки для скрипта установки консольной версии |

Переменные окружения можно явно задать в окружении команды запуска. Конфигурация по умолчанию, поставляемая с клиентом, — [config/README.md](config/README.md).

## Упаковка

Генерацию сторонних уведомлений, процесс проверки релиза и расположение уведомлений в артефактах см. в [third-party/README.md](third-party/README.md).

### Десктопная версия

```bash
pnpm bundle:desktop

# Указание целевой платформы и архитектуры CPU
pnpm bundle:desktop -- --os win --arch x64

pnpm bundle:desktop -- --help
```

Цель по умолчанию — macOS arm64, каталог вывода по умолчанию — `packages/desktop/dist/`. Флаг `--os` поддерживает `mac`, `win`, `linux`; `--arch` — `x64`, `arm64`; для фактической упаковки и подписи нужны инструменты и конфигурация целевой платформы.

Установка: откройте полученный DMG двойным щелчком и перетащите ZCode в «Программы». Локальная сборка не подписана; если macOS заблокирует первый запуск, выполните:

```bash
sudo xattr -rd com.apple.quarantine /Applications/ZCode.app
```

### Консольная версия ZCode

Точка входа сборки — `pnpm build:zcode`. Скрипт последовательно собирает CLI/TUI, серверную часть и Web, собирает нативные библиотеки, worker'ы и runtime-зависимости TUI, затем собирает релизный пакет; для запуска пакета по-прежнему нужен Node.js, версия указана в `mise.toml`.

Перед упаковкой обязательно задайте корневой адрес загрузки `ZCODE_DIST_BASE_URL` (можно в `.env`, `.env.local` или в переменной окружения); его также можно передать через `--base-url`. Указанные ниже адреса — примеры-заглушки, при публикации замените их на реальный адрес хостинга:

```bash
pnpm build:zcode --base-url https://downloads.example.com/zcode/

# При настроенной ZCODE_DIST_BASE_URL
pnpm build:zcode

# Только пересборка пакета с повторным использованием артефактов сборки агента, сервера и Web
pnpm build:zcode --skip-build

# Просмотр необязательных параметров: версия, каталог вывода и др.
pnpm build:zcode --help
```

Версия по умолчанию берётся из `package.json` в корне репозитория, каталог вывода по умолчанию — `dist/zcode/`:

- `releases/<version>/zcode-<version>.tar.gz`: рабочий пакет.
- `releases/<version>/sha256.txt`: контрольная сумма.
- `latest.json`, `install.sh`: индекс версий и скрипт установки.

Полный каталог можно загрузить на настроенный корневой адрес загрузки. Скрипт установки скачивает рабочий пакет с этого адреса, по умолчанию устанавливает в `~/.zcode/runtime` и создаёт команду `zcode` в `~/.local/bin`. Каталог установки можно изменить через `ZCODE_DIST_HOME`, каталог команды — через `ZCODE_DIST_BIN_DIR`.

Пользователям старого Lite нужно перейти на указанные выше команды сборки, переменные окружения и новый скрипт установки. Новая установка не удаляет старые каталоги Lite, не мигрирует и не удаляет существующие данные сессий.

Для локальной отладки артефактов упаковки можно просто распаковать и запустить, без загрузки или установки:

```bash
zcode_version=$(node -p "require('./dist/zcode/latest.json').version")
mkdir -p dist/zcode/debug
tar -xzf "dist/zcode/releases/$zcode_version/zcode-$zcode_version.tar.gz" \
  -C dist/zcode/debug
# Запуск TUI по умолчанию
node dist/zcode/debug/zcode/bin/zcode.mjs

# Запуск Web
node dist/zcode/debug/zcode/bin/zcode.mjs --web \
  --workspace "$PWD" --port 3030 --no-open
```

Откройте `http://127.0.0.1:3030` в браузере, чтобы проверить полную цепочку, в которой один серверный сервис раздаёт и веб-страницу, и агента. Этот порт должен быть свободен; если `pnpm dev:web` уже запущен, используйте другой `--port`.

## Структура репозитория

| Директория                                            | Ответственность                                     |
| ----------------------------------------------------- | --------------------------------------------------- |
| `packages/desktop`                                    | Electron Main, Host, Renderer и десктопная упаковка  |
| `packages/web`                                        | Веб-клиент                                          |
| `packages/server`                                     | HTTP / WebSocket-сервисы и удалённые подключения     |
| `packages/zcode-server-cli`                           | Автономный запуск Server и управление процессами    |
| `packages/ui`                                         | Общие React-компоненты, hooks и Zustand-состояние    |
| `packages/services`                                   | Бизнес-сервисы и персистентность                    |
| `packages/shared`, `packages/rpc`, `packages/client`  | Общие протоколы и типы, RPC-фреймворк, Agent client SDK |
| `packages/provider`, `packages/provider-node`         | Общие возможности провайдеров и Node-реализация     |
| `apps/zcode-cli`                                      | Agent CLI, TUI, runtime и инструменты               |
| `scripts`, `config`, `third-party`                     | Скрипты сборки, встроенная конфигурация и материалы сторонних уведомлений |
